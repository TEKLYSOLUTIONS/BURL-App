 PRODUCT REQUIREMENTS DOCUMENT (PRD) Product Name: Multi-Sport Coaching &amp; Facility Booking Platform Version: 1.1 Status: APPROVED FOR DESIGN &amp; DEVELOPMENT Primary Market: United Kingdom Platforms: Mobile (iOS &amp; Android) Audience: Product, UX/UI Designers, Frontend Engineers, Backend Engineers, QA, Stakeholders 1. PURPOSE OF THIS DOCUMENT This PRD defines: Product vision and scope Target users and roles Functional and non-functional requirements Detailed user journeys and workflows MVP vs Future scope boundaries Design and engineering guardrails 👉 This document is the single source of truth for design and development. 2. PRODUCT VISION &amp; GOALS 2.1 Vision Statement To become the default mobile platform for discovering, booking, and managing sports coaching and facilities for children, teenagers, and adults. 2.2 Business Goals Simplify youth and amateur sports coaching bookings Increase coach utilisation and earnings visibility Enable scalable expansion to multiple sports and facilities Reduce dependency on WhatsApp, calls, and spreadsheets 2.3 User Experience Goals Booking must feel faster than messaging a coach Trust must be established within seconds Coaches must feel less admin burden Multi-player management must feel natural and intuitive 2.4 Explicit Non-Goals (MVP) Desktop-first UX Advanced analytics Automated payouts / tax handling Facility provider tooling AI recommendations 3. TARGET USERS &amp; ROLES 3.1 User Roles (MVP) Role Description Guardian (Parent) Manages and books coaching for younger players Self-Managed Player Teenager or adult managing their own coaching Coach Provides coaching services Facility Provider Future (design-only) 3.2 Role Principles One app, multiple roles Role-based navigation and workflows Same booking engine for all player types Clear separation of permissions 4. CORE DOMAIN MODEL (FOUNDATIONAL) 4.1 Player (Key Concept) A Player represents anyone receiving coaching. Types: Guardian-managed Player (child) Self-managed Player (teen/adult) Rules: All bookings are always for a Player Player context is always explicit in UI 4.2 Coach Service provider Owns availability and session definitions Receives earnings per completed session 4.3 Session A scheduled coaching activity. Session types: One-to-One Group Session Attributes: Coach Date &amp; time Capacity (group) Participants (players) Status (upcoming / completed) 4.4 Booking Created by Guardian or Self-managed Player Reserves a session slot One booking = one player 4.5 Earnings (MVP – Read Only) Earnings tracked per session Aggregated by period Informational only (no payouts in MVP) 4.6 Facility (Future) Bookable sports venue Optional link to sessions Availability independent of coaches 5. PRODUCT SCOPE 5.1 MVP INCLUDES Guardian &amp; self-managed players Coach onboarding &amp; availability 1:1 and group sessions Session booking Session feedback Coach earnings tracking (read-only) Multi-sport support (data-level) 5.2 MVP EXCLUDES Facility booking UI Payment automation Refunds &amp; invoices Desktop experience Advanced analytics 6. INFORMATION ARCHITECTURE &amp; NAVIGATION 6.1 App Structure Mobile-first Bottom navigation Max 5 tabs 6.2 Guardian / Player Navigation Home Book Players (hidden for self-managed) Sessions Profile 6.3 Coach Navigation Home Availability Sessions Players Earnings Profile 7. DETAILED USER JOURNEYS &amp; WORKFLOWS 7.1 Guardian Onboarding App launch Login (phone/email) Select role → Guardian Mandatory player creation Player becomes active context Land on Home 7.2 Self-Managed Player Onboarding App launch Login Select role → Player Confirm “I’m booking for myself” Complete profile Land on Home 7.3 Discover Coach Open Book tab Browse or search Apply filters (sport, age, level, distance) Select coach card Open coach profile 7.4 Coach Profile Review Experience &amp; certifications Ratings &amp; reviews Session types (1:1 / Group) Availability preview Book CTA 7.5 Book 1:1 Session Select session type Select date Select time Confirm player Confirm booking Show confirmation 7.6 Book Group Session Select group session View capacity &amp; remaining slots Select date/time Confirm player Confirm booking 7.7 View &amp; Manage Sessions (Player/Guardian) Upcoming sessions list Past sessions list Session details Feedback view 7.8 Coach Onboarding Login Select role → Coach Create profile Define session types Set availability Land on Coach Home 7.9 Coach Availability Management Calendar-based Slot creation/editing Conflict prevention 7.10 Coach Group Session Management Define capacity View participant list Submit feedback per player or generic 7.11 Coach Earnings Tracking Open Earnings tab View total earnings View monthly breakdown View session-level earnings 8.
